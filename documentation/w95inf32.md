# W95INF32 / W95INF16 compatibility audit

## Provenance and boundary

- **Water module:** `dlls/w95inf32` (new Win9x i386 compatibility
  layer). The independent Win16 `SETUPX.DLL` implementation lives at
  `dlls/setupx.dll16`, with reusable INF operations in `dlls/setupapi`.
- **Historical source:** Wine-devel, March 2004, Mike McCormack,
  "W95INF32 implementation, incase it's useful to anybody":
  <https://list.winehq.org/hyperkitty/list/wine-devel@list.winehq.org/2004/4/>.
  It described a Win9x/IE-specific 32-bit adapter around `SETUPX`.
  **That patch was explicitly exploratory**, not a Microsoft ABI contract.
- Historical source lists four stdcall-decorated API names and
  `w95thk_ThunkData32`, ordinal 1 through 5.
  `W95INF16.DLL` is a separate NE thunk companion, **not implemented**
  by this module.

## Verified local facts

1. `setupx.dll16/setupx16.h` declares `GENINSTALL_DO_*` flags. They
   differ numerically from `SPINST_*` flags in `include/setupapi.h`.
2. `setupx.dll16/infparse.c` maps those flags before calling
   `SetupInstallFromInfSectionA`, and performs `[Strings]`
   substitutions for `GenFormStrWithoutPlaceHolders16`.
3. `setupapi/dirid.c` only permits user directory IDs `>= DIRID_USER`
   for `SetupSetDirectoryIdA`. The Win16 LDD table has separate behavior.
4. The historical `GenInstall32@20` spelling requires 20 bytes of
   i386 stdcall stack arguments, but the 2004 sketch's implementation
   showed **four** parameters. The fifth slot is *not identified*.

## Implementation admission and limitations

- The `@8`, `@12`, and `@20` names and ordinals are historical
  hypotheses supported by the 2004 source; compare against a native
  Windows 95/98 export directory before claiming exact coverage.
- `CtlSetLddPath32` forwards only Win16-sized **user** directory IDs;
  system LDD IDs intentionally return `ERROR_CALL_NOT_IMPLEMENTED`.
  The historical 32-bit function's first parameter was not proven to
  be a numeric LDID; do not use this code as native-ABI proof.
- `GenFormStrWithoutPlaceHolders32` substitutes named `[Strings]`
  references only. Numeric LDIDs, recursion, and original return-value
  semantics are not verified. There is no destination-size parameter;
  the caller must provide at least `MAX_INF_STRING_LENGTH` bytes.
- `GenInstall32` maps the well-defined Win16 flags to `SPINST_*`.
  Unsupported flags and a nonzero **unverified fifth argument** fail
  before the installer is invoked. The interpretation of 32-bit flags
  requires native call-site verification.
- `GetSETUPXErrorText32` and thunk data lack validated layouts;
  do not write through guessed pointers or invent a functioning
  Win16 thunk.
- Compiled tests, true import/export-name inspection, Windows 95/98
  installer execution, and `W95INF16` interoperability remain **unverified**.

## Next evidence gates

Obtain a legitimately distributable native Win95/98 `W95INF32.DLL`
export directory and at least one caller trace. Verify the exact
decorations, ordinal 5 symbol type, `GenInstall32`'s fifth argument,
the two-argument LDD contract, and result/error conventions before
expanding behavior. Do not infer them from the newer NT setup path.
